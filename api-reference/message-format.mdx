---
title: Message format
description: The one grammar every endpoint uses to describe a message - text, template, interactive, media, location and contact.
---

Every endpoint that sends a message (start a conversation, reply, Shortext inbound, v1.0 send) and every message in a response or a webhook uses the same `message` object:

```json
{
  "type": "text",
  "content": { "text": "Hello, how can I help?" }
}
```

`type` is one of `text`, `template`, `interactive`, `media`, `location` or `contact`; `content` depends on it.

| Type | Use it for | WhatsApp 24-hour window |
| --- | --- | --- |
| `text` | Plain text | Inside only |
| `template` | Approved WhatsApp templates | Inside and outside |
| `interactive` | Reply buttons, links, flows, payment requests, carousels | Inside only |
| `media` | Images, videos, documents, audio, stickers | Inside only |
| `location` | A position or a place on a map | Inside only |
| `contact` | A contact card the customer can save | Inside only |

Each endpoint accepts the types that make sense for it: for example a Shortext inbound message is `text` only.

## Text

<ParamField body="content.text" type="string" required>
  The text, up to **4,096 characters**. On WhatsApp, a URL in the text is rendered as a link.
</ParamField>

```json
{ "type": "text", "content": { "text": "Your order A-1042 has left our warehouse." } }
```

## Template

<ParamField body="content.template_name" type="string" required>
  The template name, as listed by `GET /templates`.
</ParamField>
<ParamField body="content.language" type="string" required>
  The template language, for example `fr` or `en_US`. The template must be approved in this language.
</ParamField>
<ParamField body="content.body" type="object">
  The body variables, by name: `{ "name": "Brice", "order": "A-1042" }`. For templates with numbered variables (`{{1}}`, `{{2}}`), give a list of WhatsApp parameters in order.
</ParamField>
<ParamField body="content.header" type="object">
  For a **text** header with variables: `{ "name": "value" }`. For a **media** header: `{ "url": "https://..." }` (and `filename` for a document). Without `url`, the media stored with the template is sent.
</ParamField>
<ParamField body="content.buttons" type="object">
  The value of each button that needs one, by its index (from 0, as listed by `GET /templates`): `{ "0": "A-1042", "1": "SAVE20" }`. The end of a dynamic link, the coupon of a copy-code button, or the payload of a quick reply.
</ParamField>
<ParamField body="content.code" type="string">
  For an **authentication** template only: the one-time code (up to 15 characters). Shortext puts it in the body and in the code button.
</ParamField>

```json
{
  "type": "template",
  "content": {
    "template_name": "order_shipped",
    "language": "fr",
    "header": { "url": "https://cdn.example.com/parcels/A-1042.jpg" },
    "body": { "name": "Brice", "order": "A-1042" }
  }
}
```

The billing category is the one Meta approved for the template. In v2.0, Shortext checks a template before sending it to WhatsApp and answers `1002` with an explicit message when the template does not exist on the number, is not approved in that language, or misses a variable (`body.missing` lists them). See [Send a template](/api-reference/guides/send-a-template).

## Interactive

<ParamField body="content.type" type="string" required>
  `button` (reply buttons), `cta_url` (a button that opens a link), `flow`, `payment` or `carousel`. Their `action` is described in [WhatsApp message types](/api-reference/whatsapp-messages).
</ParamField>
<ParamField body="content.body" type="string" required>
  The text of the message.
</ParamField>
<ParamField body="content.action" type="array | object" required>
  For `button`: a list of 1 to 3 buttons `{ "id", "title" }` (title up to 20 characters). For `cta_url`: `{ "parameters": { "display_text", "url" } }`. For the other types, see [WhatsApp message types](/api-reference/whatsapp-messages).
</ParamField>
<ParamField body="content.header" type="object">
  `{ "type": "text" | "image" | "video" | "document", "value": "text or URL", "filename": "for documents" }`. A text header is limited to 60 characters; `cta_url` accepts a text or an image header.
</ParamField>
<ParamField body="content.footer" type="string">
  Up to 60 characters.
</ParamField>

<CodeGroup>
```json Reply buttons
{
  "type": "interactive",
  "content": {
    "type": "button",
    "header": { "type": "text", "value": "Delivery" },
    "body": "When should we deliver your order?",
    "footer": "Choose a slot",
    "action": [
      { "id": "slot_morning", "title": "Morning" },
      { "id": "slot_evening", "title": "Evening" }
    ]
  }
}
```

```json Call-to-action link
{
  "type": "interactive",
  "content": {
    "type": "cta_url",
    "body": "Invoice A-1042 is ready: 25,000 XAF.",
    "action": {
      "parameters": { "display_text": "Pay now", "url": "https://www.example.com/pay/A-1042" }
    }
  }
}
```
</CodeGroup>

See what they look like on WhatsApp in [WhatsApp message types](/api-reference/whatsapp-messages).

## Media

<ParamField body="content.media_type" type="string" required>
  `image`, `video`, `document`, `audio` or `sticker`.
</ParamField>
<ParamField body="content.media_url" type="string" required>
  A public URL Shortext can download the file from.
</ParamField>
<ParamField body="content.caption" type="string">
  Up to 1,024 characters (not for audio and stickers).
</ParamField>
<ParamField body="content.filename" type="string">
  The file name shown for a document.
</ParamField>
<ParamField body="content.mime" type="string">
  The MIME type, for example `application/pdf`.
</ParamField>

```json
{
  "type": "media",
  "content": {
    "media_type": "document",
    "media_url": "https://cdn.example.com/invoices/A-1042.pdf",
    "filename": "Invoice A-1042.pdf",
    "caption": "Your invoice"
  }
}
```

### Sticker

A sticker is a `media` message with `media_type` `sticker`: a **WebP** image of **512 x 512** pixels, **100 KB** at most (**500 KB** if animated), without caption.

```json
{
  "type": "media",
  "content": {
    "media_type": "sticker",
    "media_url": "https://cdn.example.com/stickers/thanks.webp"
  }
}
```

## Location

<ParamField body="content.latitude" type="number" required>
  From `-90` to `90`.
</ParamField>
<ParamField body="content.longitude" type="number" required>
  From `-180` to `180`.
</ParamField>
<ParamField body="content.name" type="string">
  The name of the place, up to 255 characters.
</ParamField>
<ParamField body="content.address" type="string">
  Its address, up to 1,000 characters.
</ParamField>

```json
{
  "type": "location",
  "content": {
    "latitude": 3.8667,
    "longitude": 11.5167,
    "name": "Acme Bastos",
    "address": "Rue 1.750, Bastos, Yaoundé"
  }
}
```

With a `name` **and** an `address`, the place shows as a place card; otherwise as a position on a map.

## Contact

<ParamField body="content.firstname" type="string" required>
  The first name (or the name of the service), up to 255 characters.
</ParamField>
<ParamField body="content.lastname" type="string">
  Up to 255 characters.
</ParamField>
<ParamField body="content.phones" type="array" required>
  1 to 5 numbers `{ "number", "type" }`. `type` is `cell` (default), `main`, `iphone`, `home` or `work`.
</ParamField>

```json
{
  "type": "contact",
  "content": {
    "firstname": "Customer service",
    "lastname": "Acme",
    "phones": [
      { "number": "+237 6 99 99 99 99", "type": "work" },
      { "number": "+237 2 22 22 22 22", "type": "main" }
    ]
  }
}
```

## Rendering by channel

| Message | WhatsApp | Telegram | Email | Shortext endpoint |
| --- | --- | --- | --- | --- |
| `location` | A position, with the name and the address when given | A named place with a name and an address, otherwise a position | Text: name, address and a Google Maps link | The structured data, as is |
| `contact` | A contact card | A contact card: one number shown, the others in the card | Text: name and numbers | The structured data, as is |
| Sticker | A sticker | A sticker | An attachment | The structured data, as is |

## Messages in responses and webhooks

Messages returned by the API and sent in `message.*` webhooks wrap the same object:

```json
{
  "id": "k5Rz8pQw",
  "conversation_id": "c9Lw3nYb",
  "direction": "inbound",
  "channel": "whatsapp",
  "channel_id": "532867649916076",
  "contact": { "identifier": "237699999999", "identifier_type": "phone", "profile": { "firstname": "Brice" } },
  "message": {
    "id": "wamid.HBgM...",
    "type": "text",
    "content": { "text": "Hello, where is my order?" }
  },
  "status": "received",
  "created_at": "2026-10-24T09:12:44+00:00"
}
```

- `direction` is `inbound` (from the contact) or `outbound` (from the AI agent, a member of your team or the API).
- `message.id` is the id on the channel (WhatsApp message id; on a Shortext endpoint, your own message id).
- A position shared by a contact (WhatsApp or Telegram) arrives with `message.type` `location` and its `content` (`latitude`, `longitude`, `name`, `address`); its readable text is "name, address, map link". On Telegram, a phone number shared by a contact arrives with the type `contacts`. The AI agent reads these messages and answers them.
- `status` is `received` for inbound messages, then `sent`, `delivered`, `read` or `failed` for outbound ones; changes are pushed by the `message.status` webhook.

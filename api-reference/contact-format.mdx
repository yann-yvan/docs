---
title: Contact format
description: How the API identifies and describes a contact, on every channel.
---

Every endpoint that addresses a contact uses the same `contact` object:

```json
{
  "identifier": "237699999999",
  "profile": {
    "lastname": "Mbarga",
    "firstname": "Brice",
    "email": "brice@example.com",
    "address": "Douala",
    "preferred_language": "fr"
  }
}
```

## Identifier

<ParamField body="identifier" type="string" required>
  The identity of the contact on the channel, up to 200 characters.
</ParamField>

| Channel | Identifier | `identifier_type` |
| --- | --- | --- |
| WhatsApp | The phone number in E.164 format **without** the `+`, for example `237699999999` | `phone` |
| Mailbox | The email address | `email` |
| Shortext endpoint | Your own user id (`user-42`), or a phone number, an email address or a username, as set by `identifier_type` | `external_id` by default |

### Identifier type on a Shortext endpoint

<ParamField body="identifier_type" type="string" default="external_id">
  Shortext endpoints only: what the `identifier` is. `external_id`, `phone`, `email` or `username`.
</ParamField>

| `identifier_type` | `identifier` |
| --- | --- |
| `external_id` (default) | Any value of yours, up to 200 characters, for example `user-42`. |
| `username` | A username, up to 200 characters. |
| `phone` | A phone number. It is normalized like a WhatsApp number: digits only, international format without `+`. `+237 6 90 00 00 01` is stored as `237690000001`. |
| `email` | A valid email address, matched exactly as given (same case). |

The identifier is stored and returned as you give it (normalized for `phone`).

With `phone` or `email`, your user is **the same contact** as on WhatsApp or by email: a user who writes in your app and on your WhatsApp number is recognized as one person. Searching by identifier (`GET /conversations?contact=`, the [contact knowledge](/api-reference/guides/agent-knowledge#contact-knowledge) of the agent) then finds both channels, and the contact can also be reached by your WhatsApp and email [campaigns](/api-reference/guides/send-a-campaign).

On WhatsApp and mailboxes, `identifier_type` is ignored: the channel sets the type.

## Profile

All the profile fields are optional when you start a conversation or send an inbound message (the v1.0 `POST /messages/send` requires `lastname`).

| Field | Type | Notes |
| --- | --- | --- |
| `lastname` | string | Up to 250 characters. |
| `firstname` | string | Up to 250 characters. |
| `email` | string | A valid email address. |
| `address` | string | Up to 250 characters. |
| `preferred_language` | string | `en`, `fr`, `es` or `de`. |

The profile updates the contact Shortext keeps; the agent uses the name and the language to address the contact.

## Contacts in responses and webhooks

Responses and webhooks describe a contact with its identifier, its type, its profile and, when known, its country:

```json
{
  "identifier": "237699999999",
  "identifier_type": "phone",
  "profile": { "lastname": "Mbarga", "firstname": "Brice", "preferred_language": "fr" },
  "country": { "iso_code": "CM", "phone_code": "237", "name": "Cameroun" }
}
```

Empty profile fields are left out.

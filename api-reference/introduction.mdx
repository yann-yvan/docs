The Shortext API lets your systems send messages, follow conversations, manage agents and channels, receive webhooks and onboard your own clients' channels. It is a JSON over HTTPS API.

## Base URLs

| Version | Base URL | Status |
| --- | --- | --- |
| **v2.0** | `https://shortext.ny-corp.io/api/v2.0` | Current, use it for every new integration |
| v1.0 | `https://shortext.ny-corp.io/api` | Legacy, see [v1.0](/api-reference/v1.0/introduction) |

Send `Accept: application/json` and, with a body, `Content-Type: application/json`. Authenticate every request with an [API key](/api-reference/authentication).

## Response envelope

Every response has the HTTP status **200**, whether the request succeeded or not (the only exception is a removed API version, see [Versioning](/api-reference/versioning)). The outcome is in the body:

```json Success
{
  "success": true,
  "message": "Request success.",
  "code": 1000,
  "body": { "id": "AGI-XXXXX", "name": "Support" }
}
```

```json Failure
{
  "success": false,
  "message": "Missing the permissions.manage_integrations permission",
  "code": 1005,
  "body": null,
  "trace_id": "6f1c2e..."
}
```

| Field | Description |
| --- | --- |
| `success` | `true` when the request succeeded. Check it first. |
| `code` | `1000` on success, otherwise an [error code](/api-reference/errors). |
| `message` | A human-readable description. Do not parse it. |
| `body` | The result: an object, a list, a paginated list, or `null`. On validation errors, the errors per field. |
| `trace_id` | On failures only: give it to the support team to find your request. |

<Warning>Do not rely on the HTTP status to detect errors: always read `success` and `code`.</Warning>

## Pagination

Lists are paginated, 50 items per page, most recent first unless stated otherwise. Ask for a page with `?page=2`. The `body` of a paginated response is:

```json
{
  "current_page": 1,
  "data": [ { "id": "AGI-XXXXX", "name": "Support" } ],
  "first_page_url": "https://shortext.ny-corp.io/api/v2.0/agents?page=1",
  "from": 1,
  "last_page": 3,
  "last_page_url": "https://shortext.ny-corp.io/api/v2.0/agents?page=3",
  "next_page_url": "https://shortext.ny-corp.io/api/v2.0/agents?page=2",
  "path": "https://shortext.ny-corp.io/api/v2.0/agents",
  "per_page": 50,
  "prev_page_url": null,
  "to": 50,
  "total": 128
}
```

Follow `next_page_url` until it is `null`.

## Dates and ids

- Dates are ISO 8601 strings, for example `2026-10-24T09:12:44+00:00`.
- Ids are opaque strings (`AGI-XXXXX`, `ste_...`, uuids). Store them as strings, never parse them.

## What is in the API

| Resource | What you can do |
| --- | --- |
| Account | `GET /me`: the company and the key behind your token |
| Agents | Create, update, delete and restore agents |
| Channels | List channels, attach them to agents; create and manage Shortext endpoints |
| Conversations | List, read, start, reply, take over, hand back, assign |
| Templates | List the WhatsApp templates you can send |
| Webhooks | Manage endpoints, test them, read and retry deliveries |
| Hosted sessions | Let your clients connect their WhatsApp number or mailbox on a Shortext page |

The full list is in **Endpoints**, generated from the OpenAPI specification.

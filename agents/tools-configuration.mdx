---
title: Tools
description: Let an agent call your own APIs to look up or change data while it answers a customer.
---

A tool is one of your HTTP APIs that an agent can call during a conversation: fetch an order, check a balance, create a booking. The AI decides when to call a tool from its name and description, fills the parameters from the conversation, and uses the response to answer.

## Open the tools of an agent

Open the agent in **Communication > AI Agents** and go to its **API Connectors** tab.

<Frame>
  <img src="/images/agents/api-tab.png" alt="API connectors tab of an agent" />
</Frame>

## Add a tool

<Frame>
  <img src="/images/agents/add-api.png" alt="Adding a tool" />
</Frame>

- **Name**: unique, in snake_case, for example `get_order` or `confirm_payment`.
- **State**: whether the agent may use the tool. Disable it while your API is under maintenance.
- **Description**: what the tool does and when to use it. The AI relies on it to decide, so be explicit:

```text
Returns the status and the delivery date of an order from its reference (for example A-1042).
Use it when the customer asks where their order is.
```

## Define the endpoint and headers

<Frame>
  <img src="/images/agents/api-endpoints.png" alt="Endpoint of a tool" />
</Frame>

- **Method**: `GET`, `POST`, `PUT`, `DELETE`...
- **URL**: the full URL of your API, for example `https://api.example.com/orders/{reference}`.
- **Headers**: authentication and content type, for example `Authorization: Bearer ...`.

<Note>Secrets stored in headers are encrypted.</Note>

## Define the parameters

<Frame>
  <img src="/images/agents/api-body.png" alt="Parameters of a tool" />
</Frame>

Each parameter has:

- a **name**, unique within the tool, for example `reference`;
- a **type**: `STRING`, `INTEGER` or `BOOLEAN`; a `STRING` can be limited to a list of possible values;
- a **mandatory** flag;
- a **description** telling the AI how to fill it, for example "The order reference, such as A-1042".

## Return responses the AI understands

Return JSON or plain text whose meaning is clear without your internal documentation:

```json
{
  "success": true,
  "message": "Order found",
  "body": {
    "reference": "A-1042",
    "status": "shipped",
    "estimated_delivery": "2026-10-28"
  }
}
```

Prefer explicit field names and short messages; on errors, return a sentence the AI can relay, such as "No order found with this reference".

## Test a tool

Use **Debug** on an endpoint to call it with sample parameters and see the response before the agent uses it.

<Frame>
  <img src="/images/agents/api-tester.png" alt="Testing a tool" />
</Frame>

## Monitor the calls

The **Connectors Logs** of the agent list every call: time, parameters, response status and duration, and errors.

<Frame>
  <img src="/images/agents/api-logs.png" alt="Logs of the tool calls" />
</Frame>

<Warning>A tool that fails often makes the agent's answers worse. Check the logs after each change of your API.</Warning>

## Examples

| Use | Tool | Endpoint |
| --- | --- | --- |
| Look up a customer | `get_customer` | `GET /customers/{phone}` |
| Track an order | `get_order` | `GET /orders/{reference}` |
| Confirm a payment | `confirm_payment` | `POST /payments/verify` |
| Open a request in your system | `create_request` | `POST /requests` |

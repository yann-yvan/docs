---
title: Format des contacts
description: Comment l'API identifie et décrit un contact, sur chaque canal.
---

Tous les endpoints qui s'adressent à un contact utilisent le même objet `contact` :

```json
{
  "identifier": "237699999999",
  "profile": {
    "lastname": "Mbarga",
    "firstname": "Brice",
    "email": "brice@example.com",
    "address": "Douala",
    "preferred_language": "fr"
  }
}
```

## Identifiant

<ParamField body="identifier" type="string" required>
  L'identité du contact sur le canal, jusqu'à 200 caractères.
</ParamField>

| Canal | Identifiant | `identifier_type` |
| --- | --- | --- |
| WhatsApp | Le numéro au format E.164 **sans** le `+`, par exemple `237699999999` | `phone` |
| Boîte mail | L'adresse e-mail | `email` |
| Endpoint Shortext | Votre propre identifiant utilisateur (`user-42`), ou un numéro de téléphone, une adresse e-mail ou un nom d'utilisateur, selon `identifier_type` | `external_id` par défaut |

### Type d'identifiant sur un endpoint Shortext

<ParamField body="identifier_type" type="string" default="external_id">
  Endpoints Shortext uniquement : la nature de `identifier`. `external_id`, `phone`, `email` ou `username`.
</ParamField>

| `identifier_type` | `identifier` |
| --- | --- |
| `external_id` (par défaut) | Une valeur libre, jusqu'à 200 caractères, par exemple `user-42`. |
| `username` | Un nom d'utilisateur, jusqu'à 200 caractères. |
| `phone` | Un numéro de téléphone. Il est normalisé comme un numéro WhatsApp : chiffres seuls, format international sans `+`. `+237 6 90 00 00 01` est enregistré `237690000001`. |
| `email` | Une adresse e-mail valide, comparée telle quelle (même casse). |

L'identifiant est enregistré et renvoyé tel que vous le donnez (normalisé pour `phone`).

Avec `phone` ou `email`, votre utilisateur est **le même contact** que sur WhatsApp ou par e-mail : un utilisateur qui écrit dans votre application et sur votre numéro WhatsApp est reconnu comme une seule personne. La recherche par identifiant (`GET /conversations?contact=`, les [connaissances de contact](/fr/api-reference/guides/agent-knowledge#connaissances-de-contact) de l'agent) retrouve alors les deux canaux, et le contact devient aussi joignable par vos [campagnes](/fr/api-reference/guides/send-a-campaign) WhatsApp et e-mail.

Sur WhatsApp et les boîtes mail, `identifier_type` est ignoré : le canal fixe le type.

## Profil

Tous les champs du profil sont facultatifs quand vous démarrez une conversation ou envoyez un message entrant (le `POST /messages/send` de la v1.0 exige `lastname`).

| Champ | Type | Remarques |
| --- | --- | --- |
| `lastname` | string | Jusqu'à 250 caractères. |
| `firstname` | string | Jusqu'à 250 caractères. |
| `email` | string | Une adresse e-mail valide. |
| `address` | string | Jusqu'à 250 caractères. |
| `preferred_language` | string | `en`, `fr`, `es` ou `de`. |

Le profil met à jour le contact que Shortext conserve ; l'agent utilise le nom et la langue pour s'adresser au contact.

## Les contacts dans les réponses et les webhooks

Les réponses et les webhooks décrivent un contact avec son identifiant, son type, son profil et, quand il est connu, son pays :

```json
{
  "identifier": "237699999999",
  "identifier_type": "phone",
  "profile": { "lastname": "Mbarga", "firstname": "Brice", "preferred_language": "fr" },
  "country": { "iso_code": "CM", "phone_code": "237", "name": "Cameroun" }
}
```

Les champs de profil vides sont omis.

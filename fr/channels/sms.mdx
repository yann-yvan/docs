Le canal SMS envoie vos messages par SMS sur le téléphone de vos contacts. Vos messages sont signés de votre **Sender ID**, le nom affiché comme expéditeur sur le téléphone (par exemple `ACME`), et passent par la même API de messages que les autres canaux.

Shortext ouvre le SMS d'abord au **Cameroun**, puis dans d'autres pays d'Afrique.

## Votre Sender ID

Le Sender ID est le nom que vos contacts voient comme expéditeur de vos SMS. Vous ne gérez que ce Sender ID : Shortext s'occupe des routes vers les opérateurs mobiles.

Un Sender ID ne peut écrire aux clients d'un opérateur (par exemple MTN ou Orange) qu'une fois **validé par cet opérateur**. Shortext se charge des validations pour vous, opérateur par opérateur.

Shortext peut aussi vous donner accès à un **Sender ID partagé** : un Sender ID de test, ou un Sender ID de Shortext pour vos communications. Sur un Sender ID partagé de communication, Shortext vérifie le contenu de vos messages avant leur envoi.

## Envoyer un SMS

Le SMS utilise la même API de messages que les autres canaux, avec un `message` au [format des messages](/fr/api-reference/message-format). Le canal SMS n'accepte que le **texte** :

```json
{
  "type": "text",
  "content": { "text": "Votre commande A-1042 a quitté notre entrepôt." }
}
```

Tout autre type (modèle, interactif, média, position, contact) est refusé.

## Ce qui revient

- **Accusés de réception** : le statut de chaque SMS est mis à jour au fil des retours de l'opérateur (remis, ou non remis) et envoyé par le [webhook](/fr/api-reference/webhooks) `message.status`. Les accusés peuvent arriver dans le désordre : Shortext garde le statut le plus avancé.
- **Réponses** : quand l'opérateur les transmet, les réponses de vos contacts entrent dans la conversation, comme sur tout canal : l'Inbox, l'agent et le webhook `message.received`. Dans beaucoup de pays, les réponses à un SMS envoyé sous un Sender ID ne parviennent pas à l'expéditeur : n'en dépendez pas.
- **Désinscription** : un contact qui répond « Stop » est désabonné.

Le SMS est facturé **par segment**, à un tarif propre au canal SMS. Voir [Solde et mouvements du portefeuille](/fr/api-reference/guides/balance).
